## Story

**As a** innovation team researcher,
**I want** successful pipeline experiments automatically saved as reusable examples,
**so that** the system can learn from manually curated "Good" outputs without requiring technical expertise

## Context

This is **Part 1 of 3** for the complete few-shot learning system:
- **11.3a** (this story): Storage + Auto-Save (Foundation)
- **11.3b**: Example Selection + Prompt Injection (Core Logic)
- **11.3c**: Usage Tracking + Curation Interface (Enhancement)

## Acceptance Criteria

1. **Example Storage**: Organized folder structure by stage (`/successful_examples/stage_0/` through `stage_6/`)
2. **JSON Schema**: Standardized format with metadata (run_id, timestamp, brand, quality_score, inputs, outputs)
3. **Auto-Save**: "Good" tagged experiments automatically exported from Gradio UI
4. **Complete Context**: Saves full pipeline context (inputs, outputs, prompts used, metadata)
5. **Unique IDs**: Generated for each example with timestamp and hash
6. **Metadata Files**: Stage-level metadata tracking example count and usage stats
7. **Version Control**: Example library tracked in git with `.gitignore` for temporary files
8. **File Validation**: JSON structure validated before save
9. **Error Handling**: Graceful failure if save operation fails (doesn't break pipeline)
