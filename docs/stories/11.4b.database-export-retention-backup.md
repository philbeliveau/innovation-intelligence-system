# Story 11.4b: Database Export + Retention + Backup

## Status

Draft

## Architecture Reference

📘 **Implementation Guide:** `/docs/architecture/database-design.md`

This guide contains:

- Archival before deletion patterns

## Story

**As a** innovation team researcher,
**I want** to export experiments, configure data retention, and ensure backups are maintained,
**so that** I can analyze data externally and protect against data loss while managing storage costs

## Dependencies

**Depends On:**
- Story 11.4a (needs database schema and CRUD operations functional)

**Required By:**
- None (optional enhancement)

**Provides:**
- JSON export functionality
- CSV export with JSONB flattening
- Retention policy (configurable via `EXPERIMENT_RETENTION_DAYS`)
- Cleanup scripts for old experiments
- Archival to Vercel Blob before deletion
- Railway PostgreSQL backup configuration
- Manual backup capability from Gradio UI

**Can Start When:**
- Story 11.4a has save/retrieve operations working
- Post-demo enhancement (optional for MVP)

## Context

This is **Part 2 of 2** for the complete experiment tracking database:
- **11.4a**: Schema + Core Operations (Foundation) ← **Prerequisite**
- **11.4b** (this story): Export + Retention + Backup (Operations)

## Acceptance Criteria

1. **Export Functionality**: Download experiments as JSON or CSV formats
2. **Bulk Export**: Export multiple experiments with filtering
3. **JSON Export**: Complete experiment data including JSONB fields
4. **CSV Export**: Flattened structure for spreadsheet analysis
5. **Gradio Integration**: Download capability in experimentation UI
6. **Data Retention**: Configurable retention policy via environment variable
7. **Cleanup Script**: Automated deletion of old experiments
8. **Archival**: Export to Vercel Blob storage before deletion
9. **Railway Backups**: Automated PostgreSQL backups configured
10. **Manual Backup**: One-click backup capability to Vercel Blob

### Integration Points

- **Gradio UI:** Export buttons and manual backup capability
- **Vercel Blob:** Archival storage for backups and old experiments
- **Railway:** PostgreSQL automated backup configuration
- **Cron Jobs:** Scheduled cleanup script execution

### Environment Variables

- `EXPERIMENT_RETENTION_DAYS` (default: 90) - Number of days to retain experiments
- `VERCEL_BLOB_READ_WRITE_TOKEN` - For archival storage
- `BACKUP_ENABLED` (default: true) - Enable/disable backup operations
