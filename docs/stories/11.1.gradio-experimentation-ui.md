## Story

**As a** innovation team researcher,
**I want** a simple web interface to upload trend reports and run the extraction pipeline,
**so that** I can quickly experiment with different brands and review generated concepts without technical expertise

## Acceptance Criteria

1. **PDF Upload**: Interface accepts trend reports up to 50MB with visual confirmation of successful extraction
2. **Brand Selection**: Users can select from 4 pre-configured brand profiles, upload custom brand profile YAML files via drag-and-drop, OR manually enter required fields (company name, industry, geography, product portfolio)
3. **Pipeline Execution**: Single button triggers pipeline with real-time progress showing current stage
4. **Output Display**: All 7 stage outputs viewable in tabbed interface with appropriate formatting (JSON/Markdown)
5. **Quality Tagging**: Users can mark runs as Good/Needs Work/Failed with optional notes
6. **Data Persistence**: All experiment data (inputs, outputs, tags, notes) saved to database
7. **Example Management**: "Good" tagged experiments automatically exported for few-shot learning
8. **Error Handling**: Clear user-friendly messages for PDF parsing, API, and pipeline failures
9. **Integration**: Successfully calls existing backend API endpoints and displays results
10. **Accessibility**: Interface runs locally at localhost:7860 and supports optional public sharing

### Integration Points

- **FastAPI Backend:**
  - Existing endpoints in `/backend/app/routes.py`:
    - `POST /pipeline/run` - Start pipeline execution
    - `GET /pipeline/status/{run_id}` - Poll execution status
    - `GET /brands/list` - List available brand profiles (if implemented)
  - Pipeline execution logic: `/backend/app/pipeline_runner.py`
  - Error handling: `/backend/app/pipeline_errors.py` (classify_error, create_error_payload)

- **Brand Profiles:**
  - Load from `/data/brand-profiles/*.yaml` with PyYAML
  - Available profiles: `lactalis-canada.yaml`, `decathlon.yaml`, `columbia-sportswear.yaml`, `mccormick-usa.yaml`
  - YAML structure (per PRD): `brand_name`, `country`, `industry`, `positioning`, `product_portfolio` (list)
  - Supporting documentation in subdirectories: colombia/, decathlon/, Lactalis/, Mcormik/

- **Database:**
  - Use `PrismaAPIClient` from `/backend/app/prisma_client.py`
  - Experiments table with JSONB storage (schema in PRD lines 268-279)
  - Fields: id (UUID), run_id, timestamp, report_text, brand_profile (JSONB), stage_outputs (JSONB), notes, quality_tag

- **Few-Shot Learning:**
  - Export manager: `/backend/experimentation/few_shot_manager.py` (Story 11.3)
  - Storage: `/backend/experimentation/successful_examples/{stage_n}/`

- **Environment Variables:**
  - `GRADIO_SERVER_PORT=7860` (default)
  - `GRADIO_SERVER_NAME=0.0.0.0` (bind to all interfaces)
  - `GRADIO_SHARE=true` (optional public URL)
  - `OPENROUTER_API_KEY` (for pipeline execution)
  - `DATABASE_URL` (Railway PostgreSQL)

- **Railway Deployment:**
  - Add to existing backend service (PRD lines 569-578)
  - Runs on port 7860 alongside FastAPI (different port)
  - Compatible with existing deployment configuration
  - Enable queue for concurrent users: `demo.queue(max_size=10, default_concurrency_limit=3)`
