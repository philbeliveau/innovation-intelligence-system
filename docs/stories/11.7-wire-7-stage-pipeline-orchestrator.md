## Context

### Problem Statement

There is a **critical architectural discrepancy** in the production system:

**TWO PIPELINE IMPLEMENTATIONS EXIST:**

1. **LEGACY 5-STAGE PIPELINE** (Currently Active - Used by ALL endpoints)
   - **Location:** `backend/app/pipeline_runner.py` (782 lines)
   - **Imports:** Lines 19-23 only import Stage1-5
   - **Used By:**
     - Gradio UI via `/run/local` endpoint (line 358-364 in `routes.py`)
     - Next.js app via `/run` endpoint (line 399 in `routes.py`)

   - **Location:** `backend/experimentation/pipeline_orchestrator.py` (400+ lines)
   - **Created:** Commit 2506e9f (Nov 20, 2025) - Story 11.2a
   - **Status:** ❌ NEVER WIRED TO ANY PRODUCTION ENDPOINT

- `backend/app/routes.py` line 358-364: Spawns thread calling `execute_pipeline_background()`

### Async Execution Pattern

The orchestrator uses async/await but FastAPI endpoint is sync. Wrapper pattern:

```python
def execute_orchestrator_background(
    run_id: str,
    pdf_text: str,
    brand_profile: Dict[str, Any],
    custom_prompts: Optional[Dict[str, str]] = None
) -> None:
    """Wrapper to run async orchestrator in sync thread context."""
    import asyncio

    orchestrator = PipelineOrchestrator(run_id=run_id)

    # Create event loop for this thread
    loop = asyncio.new_event_loop()
    asyncio.set_event_loop(loop)

    try:
        # Run async pipeline
        loop.run_until_complete(
            orchestrator.run_pipeline(
                pdf_text=pdf_text,
                brand_profile=brand_profile,
                custom_prompts=custom_prompts
            )
        )
    except Exception as e:
        logger.error(f"Pipeline orchestrator failed: {e}")
        # Update status.json with error
    finally:
        loop.close()
```

### Technical Considerations

**1. Prisma Stage Indexing:**
- Prisma API uses 1-based indexing (Stage 1-7)
- Orchestrator uses 0-based indexing (Stage 0-6)
- Conversion: `prisma_stage_num = orchestrator_stage_num + 1`

**2. Status.json Format:**
- Gradio polls `/status/{run_id}` which reads `/tmp/runs/{run_id}/status.json`
- Must maintain format: `{"status": "running", "current_stage": 2, "stages": {...}}`
- Add `update_status_file()` calls to orchestrator to maintain compatibility

**3. Markdown Formatting:**
- `backend/pipeline/output_formatters.py` has `format_stage_output()` for all 7 stages
- Orchestrator must call formatter to generate `markdown` field for UI display
- Check Stage 0 and Stage 6 formatters handle new output schemas

**4. Webhook Payload Structure:**
- Frontend expects: `{"stageNumber": 0, "stageName": "Brand Enrichment", "status": "COMPLETE", "output": {...}}`
- Verify orchestrator sends webhooks in same format as legacy pipeline

**5. Few-Shot Integration:**
- Experimentation stages already load few-shot examples from `successful_examples/`
- Verify Stage 0 and Stage 6 few-shot loaders work (if implemented)
- Ensure "Good" tagged experiments auto-export includes all 7 stages
