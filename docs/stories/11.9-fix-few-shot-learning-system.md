## Dev Notes

### Root Cause Analysis

**Problem Statement**: The few-shot learning system is broken at multiple levels:

1. **Silent Import Failure** (`gradio_lab.py:27-41`):
```python
try:
    from few_shot_manager import FileSystemExampleStorage, ExampleMetadata
    from prompt_injection import inject_few_shot_examples
except ImportError:
    try:
        from experimentation.few_shot_manager import FileSystemExampleStorage, ExampleMetadata
        from experimentation.prompt_injection import inject_few_shot_examples
    except ImportError:
        print("Warning: Few-shot learning modules not found")
        FileSystemExampleStorage = None
        inject_few_shot_examples = lambda x, y: y  # No-op
```
**Issue**: Both import paths fail silently, setting `FileSystemExampleStorage = None`. User never sees error.

2. **Export Returns Fake Success** (`gradio_lab.py:836-840`):
```python
if quality_tag == "Good" and storage is not None:
    # ... export code ...
    return 0, 7  # Always returns "0 saved, 7 failed" when storage is None
```
**Issue**: When `storage = None` (from failed import), function returns fake statistics instead of raising error.

3. **Legacy Pipeline Has No Injection** (`backend/app/pipeline_runner.py`):
- File has NO imports for `few_shot_manager` or `prompt_injection`
- Stages 1-5 execute without any few-shot example loading
- Even if examples were exported, they'd never be used

4. **Orchestrator Never Wired** (`backend/experimentation/pipeline_orchestrator.py`):
- Complete 7-stage implementation with few-shot injection built-in
- Lines 147-165 load examples and inject into prompts
- But `/run/local` endpoint calls `pipeline_runner.py`, not orchestrator
- Orchestrator only used in test files, never production

### Architecture Decision Required

**Two paths forward:**

**Option A: Enhance Legacy Pipeline (5 stages)**
- Pros: Minimal disruption, works with existing Next.js integration
- Cons: Perpetuates obsolete 5-stage architecture, missing Stage 0 & 6
- Files to modify:
  - `backend/app/pipeline_runner.py` (add few-shot imports/injection)
  - `backend/app/routes.py` line 144-162 (`/run/local` endpoint)

**Option B: Wire Orchestrator (7 stages)**
- Pros: Modern architecture, few-shot injection already built-in, includes Stage 0 & 6
- Cons: Requires testing Next.js compatibility, larger change surface
- Files to modify:
  - `backend/app/routes.py` line 144-162 (replace `pipeline_runner.execute_pipeline_background()`)
  - Import orchestrator instead of pipeline_runner
  - Verify markdown formatting compatibility

**Recommendation**: Option B (wire orchestrator) for long-term health. The 7-stage pipeline was built in Story 11.2a (commit 0343ac2) but never integrated.

### Technical Context

**Few-Shot Learning Pattern (as designed):**

1. User runs pipeline → generates outputs for Stages 0-6
2. User reviews outputs and tags experiment as "Good"
3. System exports each stage's output to `successful_examples/stage_N/experiment_{run_id}.json`
4. System updates `metadata.json` with new example count
5. Next pipeline run → system loads examples from `successful_examples/`
6. System injects examples into stage prompts using template:
```
Here are examples of high-quality outputs for this stage:

EXAMPLE 1:
[example output]

EXAMPLE 2:
[example output]

Now generate output for the current inputs:
[current prompt continues]
```

**Current Reality:**
- Steps 1-2 work (pipeline runs, user can tag)
- Step 3 FAILS SILENTLY (import broken, export never happens)
- Steps 4-6 NEVER EXECUTE (no code in legacy pipeline to load/inject)
