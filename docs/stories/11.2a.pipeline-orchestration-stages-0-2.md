## Story

**As a** innovation team researcher,
**I want** a pipeline orchestrator that executes the first 3 stages (Brand Enrichment, Trend Decomposition, Consumer Insights),
**so that** I can transform trend reports into brand-specific consumer needs through systematic processing

- Stage 2: Consumer Insights outputs

**Can Start When:**

## Context

This is **Part 1 of 3** for the complete 7-stage pipeline implementation:
- **11.2a** (this story): Orchestration + Stages 0-2 (Foundation)
- **11.2b**: Stages 3-4 (Technique Matching + Concept Generation)
- **11.2c**: Stages 5-6 + Configuration (Finalization)

## Acceptance Criteria

1. **Pipeline Orchestrator**: Async execution framework supporting 7 stages with state persistence
2. **Stage 0 - Brand Enrichment**: Transforms basic brand YAML into comprehensive context
3. **Stage 1 - Trend Decomposition**: Extracts trends with multi-level abstraction (L1-L4) and lifecycle stages
4. **Stage 2 - Consumer Insights**: Generates brand-specific consumer needs from trend analysis
5. **State Persistence**: All stage outputs saved to database with progress tracking
6. **Webhook Notifications**: Real-time status updates sent to frontend on stage completion
7. **Error Handling**: Stage-level error classification and retry logic
8. **API Integration**: Successfully called from existing `/pipeline/run` and `/pipeline/status` endpoints
9. **Performance**: Stages 0-2 complete in under 3 minutes combined

### Integration Points

- **FastAPI Backend:**
  - Existing endpoints in `/backend/app/routes.py`: `POST /pipeline/run`, `GET /pipeline/status/{run_id}`
  - Extend to support 7-stage architecture
  - Pipeline execution logic: `/backend/app/pipeline_runner.py`
  - Error handling: `/backend/app/pipeline_errors.py`

- **Brand Profiles:**
  - Load from `/data/brand-profiles/*.yaml` with PyYAML
  - Stage 0 processes and enriches these profiles

- **Database:**
  - Use `PrismaAPIClient` from `/backend/app/prisma_client.py`
  - Save stage outputs to `stage_outputs` JSONB field

- **Environment Variables:**
  - `OPENROUTER_API_KEY` (for LLM calls)
  - `PERPLEXITY_API_KEY` (for Stage 0 enrichment)
  - `DATABASE_URL` (Railway PostgreSQL)
  - `WEBHOOK_URL` (frontend status updates)
