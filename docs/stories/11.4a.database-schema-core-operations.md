## Acceptance Criteria

1. **Schema Design**: Single experiments table with UUID key and JSONB storage for stage outputs
2. **Required Fields**: run_id, timestamp, report_text, brand_profile (JSONB), stage_outputs (JSONB), quality_tag, notes
3. **Database Support**: SQLite for development, PostgreSQL for production (Railway)
4. **Auto-Migration**: Table created automatically on application startup if not exists
5. **Save Operations**: Store complete pipeline runs with all metadata
6. **Retrieve Operations**: Query by date range, brand, quality tag, or run_id
7. **Filtering**: JSONB queries for brand-specific filtering (industry, geography)
8. **Pagination**: Support for large result sets (configurable page size)
9. **Performance**: Optimized indexes for common query patterns

**Given-When-Then Patterns:**

**Scenario 1: Save Complete Experiment**
- **Given** a complete pipeline run with all metadata
- **When** `save_experiment()` is called with valid data
- **Then** experiment is stored in database with 201 response and returns experimentId

**Scenario 2: Retrieve Experiments with Filters**
- **Given** experiments exist in database
- **When** `get_experiments()` is called with quality_tag="good" and brand_name filters
- **Then** only matching experiments are returned with pagination metadata

**Scenario 3: Handle Duplicate Run ID**
- **Given** an experiment with run_id="test-123" already exists
- **When** attempt to save another experiment with same run_id
- **Then** API returns 409 Conflict error (unique constraint violation)

### Performance Considerations

✅ **Performance design is solid**

**Optimizations Implemented:**
- ✅ Composite indexes: `timestamp(sort: Desc)`, `qualityTag`, `pipelineVersion`
- ✅ JSONB storage: Efficient for flexible schema (no need for separate tables for stage outputs)
- ✅ Pagination: Prevents large result sets (default 20, max 100)
- ✅ Query optimization: `findMany` with `where`, `orderBy`, `skip`, `take`

**Known Limitation (Acceptable for MVP):**
- Brand name filtering uses in-memory post-filter due to Prisma JSONB limitations
- **Impact**: Pagination counts may be slightly off if filtering by brand_name
- **Mitigation**: For production, add raw SQL query for JSONB path queries: `WHERE brand_profile->>'brand_name' = ?`
- **Priority**: LOW - Only optimize if >1000 experiments with frequent brand filters
